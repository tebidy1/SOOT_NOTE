# Rule: Arabic-First Content and UI

## Core Principle
This project MUST be developed with an **Arabic-first** approach. All user interface (UI) text, labels, and content must be written exclusively in Arabic.

## Rationale
To ensure a fully localized and immersive experience for the target audience, we are prioritizing Arabic as the sole language for the user-facing application. This simplifies development by removing the need for a complex internationalization (i18n) library and focuses efforts on creating a high-quality Arabic experience.

## Guidelines

### 1. No Hardcoded English in UI
-   **Forbidden:** Writing static text directly in English within JSX components.
    ```tsx
    // ❌ INCORRECT
    <h1>Dashboard</h1>
    <Button>Create New Shipment</Button>
    ```
-   **Required:** All static text must be in Arabic. For consistency, use the centralized translation file.
    ```tsx
    // ✅ CORRECT
    import { ar } from "@/lib/i18n/ar";
    
    <h1>{ar.dashboard}</h1>
    <Button>{ar.newShipment}</Button>
    ```

### 2. Centralized Arabic Strings
All UI strings must be stored in and imported from a central file to ensure consistency and ease of maintenance.

-   **Location:** `src/lib/i18n/ar.ts`
-   **Usage:**
    ```typescript
    // src/lib/i18n/ar.ts
    export const ar = {
      dashboard: "لوحة التحكم",
      newShipment: "شحنة جديدة",
    };

    // In a component
    import { ar } from "@/lib/i18n/ar";
    
    <h1>{ar.dashboard}</h1>
    <Button>{ar.newShipment}</Button>
    ```

### 3. Layout and Direction (RTL)
-   The root layout (`app/layout.tsx`) is already configured with `dir="rtl"` and `lang="ar"`.
-   All styling MUST use Tailwind CSS logical properties (e.g., `ms-`, `pe-`, `text-start`) to ensure proper alignment in RTL.
-   Icons that imply direction (e.g., arrows) MUST be flipped for RTL using `rtl:rotate-180` or by using the appropriate icon variant.

### 4. Mock Data and Dynamic Content
-   While UI text must be in Arabic, mock data (like user names, cities, etc.) generated by libraries like Faker.js can remain in English for development simplicity. The primary goal is to ensure the UI "chrome" (buttons, labels, titles) is fully Arabic.

## Final Rule
Any new component, page, or feature added to this project must adhere to the Arabic-first principle from the outset. No English UI text will be accepted in pull requests without explicit justification for developer-only or debug-related content.
